## 独立的适配修正版

`results/public_harness_20260924/compact_repair_v1` 注册四个短任务的全新种子 42 运行，版本为 `airesearcher-task-transport-compact-v1`。修正来自未完成运行的执行错误，不使用其测试分数选择修正方案。

1. 阶段提示不再重复附带整份任务、设计菜单和结果。每次系统提示仍含当前完整任务及已测候选证据；原生阶段动作、继承的推理、工具结果保持，移出的重复任务包完整记入日志。
2. 兼容明确的单工具 `tool/parameters` 或 `name/parameters` 封装，等价转换成 `arguments`。不猜测工具、候选或参数值，不从多个调用中挑一个。
3. 模型、28K 输入上限、512 输出上限、调用次数、六槽位、完整训练及独立评分均不变。修正版不覆盖原始失败或自动冒充原协议完成结果。

修正版使用 GPU 0（与现有控制器共享），不占用 DTI 的七张拟合卡。额外保守计费上限为 2 GPU·小时，且不超出原队列的墙钟窗口；原队列上限 180 GPU·小时，合计上限 182，低于 8 卡一天。两个队列都有独立 PID、状态、子进程所有权和超时清理。失败不自动无限重试。

修正版成功后自动运行独立评分与复核，在 `tables/public_harness_compact_repair/` 生成独立结果。正式接入主表前核对版本与端点覆盖，不能把两种适配版本混写为一个未注明的统一协议。

V1 后续定位到 Norman 的单工具调用列表封装不兼容。最终补跑 `compact_repair_v2` 等 V1 队列退出后接续，四个短任务全部使用同一 V2 版本，重新拟合与评分，不按 V1 分数挑选复跑对象。V2 兼容完整的单调用列表及其原生封装；不挑选多调用中的某一项。额外上限 2 GPU·小时，两个修正队列与原始队列合计上限为 184 GPU·小时。发布器按已注册版本固定选 V2，而非选择分数更高的版本；V1 全部运行记录保留。

V2 进一步暴露出 AI-Researcher 会在第五个候选后按原生判断结束 refinement。把“没有强制耗尽第六个槽位”记作工具失败并不准确。最终登记的 `compact_repair_v4` 因此把 6 明确定义为候选上限：保留原生提前停止，逐项验证实际产生的 1--6 个请求，仍使用相同候选菜单、每候选 100 轮训练和原 scorer。该变化不填充候选、不复用失败运行检查点，也不依据测试分数选择是否重跑。`seed42_dti_priority_v3` 在 AI-Scientist-v2 的 DTI 完整评分后停止低优先级续跑，等待短任务结束，并用同一 V4 协议完成 AI-Researcher DTI。所有队列的累计硬上限为 192 GPU·小时，仍不超过 8 卡一天，并继承原始墙钟截止时间。最终 seed-42 表固定组合 V2 已独立验证的 PTPC 与 V4 的其余四个端点，来源在 JSON 中逐格记录。

## 已核实与落实

1. **设计与预算分离。** design_id 指定预测组件与优化设置；rounds 由执行调度器另传。主表与提案反馈研究为每个候选配置 100 轮，短训晋级是独立固定候选消融。研究提案模型不决定 epoch 数。
2. **独立训练分配消融。** 固定十个候选先各训练 20 轮。三个学习率分组分别选择最佳筛选 checkpoint 得分者，以及其余候选中第 5 到第 20 轮 primary 变化最大者，共六个；它们从各自初始参数重新训练 100 轮。其余四个完成筛选后不再训练。不是续训 80 轮，也不是一条 120 轮轨迹。两种调度都是 800 个全客户端训练轮次。
3. **晋级同分规则。** 最佳筛选得分以其对应开发 loss 破平；变化量以第 20 轮开发 loss 破平。变化最大不要求变化为正，故移除“improving trajectories”这种可能暗示正增长门槛的表述。
4. **训练一轮的含义。** 每个参与实验室从当前共享参数训练一个完整本地 AdamW epoch，再聚合一次。参数按实际训练样本数加权；可选 server momentum 作用于参数。浮点 buffer 加权平均、整数 buffer 取最大值的实现细节已在附录说明。
5. **两层选择顺序。** 每五轮及最后一轮评价同一聚合 checkpoint。各实验室开发主指标与开发 loss 都等权平均。先为每个候选选出最佳 checkpoint，再用同样的“主指标优先、较低 loss 破平”规则与 incumbent 比较。完全相等时保留更早的 checkpoint 或现有 incumbent。
6. **初始化语义。** 各候选遵循相同任务初始化规则与 seed，从头拟合。同一次候选拟合内部，各实验室参数完全相同。不同设计可增加零输出初始化的 residual 模块，不能说不同结构的全部参数张量完全相同。
7. **LLM 如何使用历史。** LLM 权重固定，但新试验摘要作为下一轮上下文输入，因此决策可依实验反馈变化。反馈卡含配置、hypothesis、最佳开发统计与轮次、首末训练/开发诊断及其变化、接受/拒绝；完整逐轮轨迹保留于 fit 记录，而不是整条都送入 LLM。
8. **通信和实验角色。** 训练接口返回本地模型状态与样本数；开发接口返回标量评价与诊断；LLM 接收聚合摘要。主表完整系统为十实验室，本地参照为一实验室；这些角色仍是在同一主机上模拟，未改成真实多机构部署叙述。

\section*{1. Introduction}
Biological algorithm development combines an uncertain scientific idea with a concrete implementation, an evaluation contract, and a decision about what to try next. A language model can contribute to each step, yet the resulting system is useful only if its decisions can be checked against code and measurements. Reproducibility therefore requires more than saving a conversation: the editable component, data visible during search, evaluation code, model calls, failures, and selected artifact must remain identifiable.

Distributed biological collaboration adds a separate difficulty. Institutions may possess complementary data while facing ownership and sharing constraints. Multi-institutional medical learning provides an established example of this motivation \citep{Sheller2020}. We ask whether local evaluation evidence can improve a shared research artifact while measurements remain with the evaluator. This motivates two empirical questions: does a structured research loop use the same evidence more effectively than direct code generation, and does a richer client-resolved diagnostic package help when the underlying observations are held fixed? Giving both controllers the local interface makes these questions testable without assuming that federation is unique to a harness.

We make three concrete contributions. First, we specify a hypothesis-to-artifact-to-evaluation interface and instantiate it with a versioned production harness, fixed scorer contracts, and evidence-backed retention or rollback. Second, we implement federated evidence-guided code updates and separate additional calibration information from distributed computation through a sufficient-statistic replay. Third, we evaluate three task families: exploratory cell-policy diagnostics, a native-controller comparison on DrugEvolve's DTI task, and a prospectively frozen proteomics study crossing direct/loop research with pooled/client-level evidence. The last study gives both controllers the same local-data interface, training recipe and executable retention rule. These comparisons separate task utility, diagnostic information and the inspectability of the research process.

\section*{1. Introduction}
Biological algorithm development combines an uncertain scientific idea with a concrete implementation, an evaluation contract, and a decision about what to try next. A language model can contribute to each step, yet the resulting system is useful only if its decisions can be checked against code and measurements. Reproducibility therefore requires more than saving a conversation: the editable component, data visible during search, evaluation code, model calls, failures, and selected artifact must remain identifiable.

Distributed biological collaboration adds a separate difficulty. Institutions may possess complementary data while facing ownership and sharing constraints. Multi-institutional medical learning provides an established example of this motivation \citep{Sheller2020}. Our design question is narrower than eliminating all leakage: can local evaluation evidence contribute to a shared, inspectable research artifact while raw measurements remain outside the model prompt? This question does not imply that direct code generation cannot use a local evaluator, nor that uploading a short statistic is inherently private.

We make three concrete contributions. First, we specify a hypothesis-to-artifact-to-evaluation interface and instantiate it with a versioned production harness, fixed scorer contracts, and evidence-backed retention or rollback. Second, we implement federated evidence-guided code updates and separate additional calibration information from distributed computation through a sufficient-statistic replay. Third, we evaluate the interface in a four-arm cell-policy study and a native-controller comparison on a DrugEvolve task family. The latter shares the public research agenda and freezes selected architectures before held-out scoring. Together, these studies measure task utility and expose the decisions, resource costs, and information boundaries behind it.

\section*{2. Related work and comparison scope}
DrugEvolve combines research, implementation, debugging, evaluation, analysis, memory, and algorithm lineage across drug-development tasks \citep{Zhou2026DrugEvolve,DrugEvolveCode}. Its manuscript reports 11 task families and 120 test sets, including external, cold, temporal, or structural evaluations where appropriate. Our comparison focuses on native controller behavior under a shared task contract, using its released Creation pipeline and local database with explicit model-transport and evaluator adaptations. Iteration, memory, lineage, and cold testing are existing capabilities of that system. The separately released DrugBAN-Evo module is an algorithm reference, distinct from rerunning the DrugEvolve controller.

DrugBAN represents drugs as molecular graphs and proteins as sequences, and uses bilinear attention to model local interactions \citep{Bai2023DrugBAN,DrugBANCode}. We reconstruct its full encoder--interaction--classifier model using the pinned original implementation, then restrict search to the BAN component. We use the non-domain-adaptation training configuration and a deliberately limited data and compute budget. Our numbers therefore do not reproduce the published full-budget DrugBAN or DrugEvolve scores.

Federated averaging aggregates locally computed parameter updates \citep{McMahan2017}. In contrast, our cell study leaves the language-model weights unchanged: clients contribute evaluation and diagnostic evidence that informs updates to executable policies. We call this federated evidence-guided search, not parameter-averaged language-model training. Parameter updates, statistics, and code can each expose information; data locality is a deployment property, not a formal privacy theorem. The present work does not implement differential privacy or secure aggregation, and a message-size cap is not a privacy budget.
